## 1. 지금 이 사이트의 재료는 거의 없다

정직하게 적는다. 발행 29편은 **공개 출처를 검증해서 영어로 재구성한 것**이다.
품질은 높다. 그러나 같은 출처(국세청·금융위·법제처)를 가진 경쟁자가 한 달이면
같은 것을 만든다. **재료가 아니라 가공이다.**

복제 불가능한 재료는 네 종류고, 현재 상태는 이렇다.

| 재료 | 복제 난이도 | 그릇 | 현재 |
|---|---|---|---|
| **A. 변경 이력** — 수치가 언제 무엇에서 무엇으로 바뀌었는지 | 시간으로만 쌓임 | ✅ 관측 DB | 8시리즈 / 12관측 / 이력 있는 시리즈 4개 |
| **B. 1인칭 절차 증거** — 실제로 겪은 화면·거절 사유·실제 청구서 | 사실상 불가 | ✅ 증거 아카이브 | **0** |
| **C. 실측 시계열** — 특정 날짜에 특정 기관이 제시한 실제 조건 | 사실상 불가 | ✅ 관측 DB | **0** |
| **D. 연결 구조** — 수백 편의 의미 있는 내부링크 | 편수에 비례 | ✅ 내부링크 계약 | 35편 수준 |

**세 층으로 본다.**

```
Layer 1 — VERIFIED     법령 / 국세청 / 금융위 / 출입국 / 은행 공식자료
      ↓
Layer 2 — OBSERVED     가격 / 금리 / 한도 / 요율의 실제 변화 기록
      ↓
Layer 3 — EXPERIENCED  실제 신청 / 거절 / 승인 / 납부 / 제출서류 / 비용
      ↓
   AUTHORITY
```

Layer 1 은 잘 하고 있다. Layer 2 는 그릇이 생겼으니 이제 시간이 채운다.
**Layer 3 은 저자가 넣지 않으면 영원히 0 이다** — 그리고 그게 진짜 해자다.

### B 가 이 사이트에서 특별한 이유

저자는 한국 법인의 대표이고 ISO 심사원이다. 즉 **직접 겪었다** —
법인 설립, 4대보험 포함 급여 지급, 부가세 신고, 외국인 관련 은행 업무.
영어권 경쟁 사이트는 이걸 못 쓴다. 한국 세무 블로그는 영어로 안 쓴다.
**"내가 실제로 냈다" 가 들어간 문장은 AI 로 조립한 사이트가 만들 수 없다.**

구체적으로 수집할 것:

- 홈택스·위택스 실제 화면 (개인정보 마스킹)
- 실제 4대보험 고지서와 그 위의 실제 숫자
- 은행이 실제로 요구한 서류 목록, 실제 거절 사유
- 실제 지출 — 법인 설립 총액, 첫 급여의 사업자 부담분

### C 가 왜 시간이 지날수록 비싸지는가

`2026-08 · KB · E-7 · 신용대출 제시금리` 한 줄은 일화다.
24개월이 쌓이면 **영어권에 존재하지 않는 데이터셋**이다. 그리고 그건
검색 트래픽이 아니라 인용과 링크를 부른다.

## 2. 지금 결정해야 하는 것 — 나중에 하면 14배

재료를 담을 자리를 스키마에 지금 만든다. **35편에 소급하는 비용과 500편에
소급하는 비용은 14배 차이**고, 그릇이 없으면 재료는 수집되지 않는다.

**관측 이력을 프론트매터에 쌓지 않는다.** 3년이면 글 하나에 관측치가 수십 개씩
붙고, 월간 감사가 245편의 원고 파일을 건드리게 된다. 글에는 "무엇을 추적하는가"
만 넣고, 값의 이력은 별도 데이터에 둔다.

```
ARTICLE                          글에는 참조만
  tracked: [minimum-wage, ...]
  evidence: [...]
  lastVerified

OBSERVATION DB                   값의 이력은 여기에
  src/data/observations/minimum-wage.json
  src/data/observations/corporate-tax-rates.json

EVIDENCE ARCHIVE                 1인칭 증거는 여기에
  src/data/evidence/*.json + public/evidence/<cluster>/
```

- [x] `content.config.ts` — `tracked` / `evidence` / `lastVerified` / `nextCheck`
      (전부 선택 필드, 기존 글 무영향)
- [x] `src/data/observations/` 관측 DB — 8개 시리즈, 검증된 실제 수치로 시딩
- [x] `src/data/evidence/` 증거 아카이브 — 레지스트리 + 작성 규칙 (현재 0건)
- [x] `scripts/lint-data.mjs` — 참조 무결성. 존재하지 않는 key 를 참조하면 빌드 실패.
      `npm run build` 가 이걸 먼저 돌린다
- [x] `/tracked/` + `/tracked/<key>/` — **원고 없이 데이터에서 생성되는 이력 페이지**
- [x] 글 하단 "이 글이 추적하는 수치" 블록 — 값이 바뀌면 JSON 한 줄 고쳐서 전부 갱신
- [x] `/calendar/` D-day 상태값 — 같은 정보인데 매일 달라짐
- [ ] `/updates/` 를 revisions + 관측 변화 통합 타임라인으로 확장
- [ ] 월간 freshness Routine (`trig_01EBo1A3vQYc42eveTZUwP6r`, 첫 발화 09-01)
      이 `tracked` + `checkMonth` 를 읽고 이번 달 재확인 대상만 뱉게 연결
- [ ] **재료 B 수집 시작** — 저자만 할 수 있는 유일한 항목

**A 는 자동화가 만들고, B·C 는 저자만 만들 수 있다.** 그래서 저자에게 요청할
것은 "글을 더 써 달라" 가 아니라 **"겪은 것의 증거를 달라"** 다.

## 3. 과실 — 지금은 0 이고, 그게 정상이다

숨기지 않고 적는다.

| 지표 | 현재 (2주차) |
|---|---|
| 노출 | 331 |
| 클릭 | 6 |
| 예상 AdSense 수익 | **월 수백 원 수준** |

금융·보험은 영어권에서 RPM 이 가장 높은 주제군이지만, RPM 이 아무리 높아도
**트래픽이 0에 가까우면 곱해서 0 이다.** 2주 된 사이트에서 수익을 논하는 건
이르다. 다만 **어떤 과실을 맺을 나무인지는 지금 정해진다.**

### 과실 4종과 이 사이트의 적합도

| 과실 | 필요한 것 | 이 사이트 | 시점 |
|---|---|---|---|
| **AdSense** | 트래픽 | 주제군 RPM 은 최상위. 트래픽만 필요 | 승인 후, 트래픽 따라 |
| **제휴 (affiliate)** | 열린 제휴 프로그램 | 한국 은행권은 대부분 없음. **송금·eSIM·여행보험은 있음** | Visit Korea (281~) 가 빠름 |
| **리드 / 서비스 연결** | 신뢰 + 1인칭 권위 | 세무사·행정사·대출상담. **단가가 가장 높음** | 재료 B 가 쌓인 뒤 |
| **자체 서비스** | 저자의 법인 | 마진 100%, 제휴 승인 불필요 | 언제든 |

**Live 트랙(001~280)의 진짜 과실은 광고가 아니라 리드다.**
"한국에서 법인 세운 외국인" 검색은 월 몇 백 회지만, 한 건의 가치가
광고 수천 회 노출보다 크다. 그리고 그건 재료 B 없이는 안 된다.

**Visit 트랙(281~500)의 과실은 제휴다.** eSIM·숙박·보험은 프로그램이 열려 있고
승인이 쉽다. 저자가 "281 이후가 수익화가 빠르다" 고 본 건 맞다.

### 지금 할 것 / 하지 말 것

- **할 것**: 글 템플릿에 전환 슬롯 위치를 정해둔다. 비워두더라도 자리는 만든다.
  500편에 소급 삽입하는 건 다시 14배다.
- **하지 말 것**: 트래픽이 없는 상태에서 제휴 신청을 돌린다. 거절 기록만 남는다.
- **하지 말 것**: 수익을 위해 글 성격을 바꾼다. 재료가 과실을 만들지,
  그 반대가 아니다.

## 4. 변화 — 다시 올 이유

검색 유입만 있는 사이트는 재방문이 0 이다. 재방문이 0 이면 브랜드도 0 이고,
알고리즘이 한 번 흔들리면 그대로 죽는다. **바뀌는 것이 있어야 한다.**

한국의 돈 규칙은 실제로 계속 바뀐다 — 그리고 **영어로 그걸 추적하는 곳이 없다.**
이게 이 사이트가 "변화" 를 만들 수 있는 이유다.

| 장치 | 상태 | 재방문 동력 |
|---|---|---|
| `/calendar/` 돈 달력 + D-day | ✅ 2026-08-31 | 같은 정보인데 **매일 상태가 달라짐** |
| `/tracked/` 추적 수치 이력 | ✅ 2026-08-31 | 수치가 움직일 때마다 자동 갱신 |
| `/updates/` 변경 이력 | ⚠️ 껍데기만 (실질 2건) | 관측 DB 와 통합 예정 |
| 월간 freshness 감사 | ✅ 09-01 첫 발화 | A 를 생산하는 엔진 |
| 계산기 4종 | ✅ | 필요할 때마다 |
| 뉴스레터 / 구독 | ❌ | A 가 쌓인 뒤에 |

**순서가 중요하다.** 뉴스레터를 먼저 만들면 보낼 게 없다.
변경 이력이 먼저 쌓이고, 그게 보낼 거리가 되면 그때 만든다.

## 5. 다윗의 시간표

도메인 권위는 단기간에 못 뒤집는다. 뒤집으려 하지 않는다. 대신:

```
1년차   재료 A·B·C 수집 시작 · 편수 확보 · 롱테일만 노림
2년차   변경 이력 12개월치 = 인용 가능한 자산 · 리드 시작
3년차   복제 원가가 경쟁자의 진입을 막는 지점
```

**진입장벽은 편수가 아니라 시간이다.** 280편은 한 달이면 AI 로 복제된다.
24개월치 변경 이력과 1인칭 증거는 24개월이 걸린다. 그게 차이다.
